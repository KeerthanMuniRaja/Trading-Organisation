# Audit of 14 October 2026: what is really done

At the owner's request, four independent read-only reviews compared every planned idea and every document with the code and its tests. A doc saying "done" was not taken as evidence. This page records the honest result: what was fixed the same day, and what remains.

## The short answer

- **Sound.** The money core works and is well tested: ledger, wallets, paper P&L, audit chain, append-only history, roles and idempotency.
- **Fixed today.** Trading, the part that live paper testing depends on, had real bugs. They are fixed and tested (below).
- **Built but not running.** Much of the organisation and learning side has a tested backend, but nothing in the daily workflow uses it. That is the largest remaining gap.
- **Partly not built.** Several planned items are only partly built. Some need the owner's decision.

## Fixed on 14 October (all with tests)

**Price evidence (strict).**
- Evidence must state exactly one price, `NSE:<share> on <date>: <price> paise`, for this share, dated on its publication day.
- The observation time is the evidence's own publication time, so a caller can no longer re-date a price or borrow another share's price.
- The same rule now covers outcome exit prices, which were previously not tied to their evidence.

**Execution integrity.**
- The back door is closed: end-of-day prices only work for reviewed proposals, and bots under release control cannot place direct orders.
- One order per proposal, stored on the order (migration 049). This makes three things safe that were not:
  - a second credential cannot double-trade;
  - a fill made just before a crash is recorded;
  - a retry with a later price resumes the same order.
- A buy whose price rose fills the shares that still fit, instead of failing every day.

**Review room.** Cancelled or already-reserved intents no longer count twice.

**Corporate actions.**
- A split recorded late rescales only the shares held through the ex-date.
- Scoring restates from the time the price was observed, not the review time.

**Smaller fixes.**
- **Alerts:** release alerts look only at each bot's current active release, so superseded versions no longer raise an alert that never clears.
- **Loss limit:** it counts trading losses only, not owner operating expenses.
- **Dates:** fitness periods use India dates.

**Rule bot.**
- It decides once a month and keeps that decision; a rerun sends only what is missing.
- In a rotation month it sells first and buys once the sale has freed the budget.

**Operations.**
- **Feeds:** a feed in back-off counts as failed, so outages escalate.
- **Readiness:** it says NO-GO when it cannot read the digest.
- **Unfinished bars:** a bar from an unfinished session is never stored.
- **Large moves:** they are kept back until the owner confirms them (`daily.py accept-move`); a confirmed move no longer freezes the share's data.
- **Manual runs:** they read `.env` correctly.
- **Halt:** live fitness skips during a halt instead of failing.

**Knowledge.**
- **Fact-checking:** loosely corroborated news waits for a person instead of being auto-verified (opt in with `looseCorroborationVerifies`).
  - *Update, 20 October:* the automatic fact-checker now uses the backend's fact-key rule, so corroborated news is auto-verified soundly again, and the loose rule and its opt-in are retired ([evidence-claims](evidence-claims.md)).
- **As-of view:** it now counts lessons accepted through the learning workflow as verified.

**Documents.** Corrected wherever they contradicted the code:
- releases, deployment and operations-cycle;
- publisher-feeds, evidence-claims, departments and security;
- alerts, bot-fitness and paper-performance;
- organisation-progress.

## Still open, in priority order

1. **Bring the learning loop into the daily cycle.**
   - Connect lessons, transfer and fresh assessment, so knowledge actually grows. Today nothing in the daily workflow turns news into verified knowledge.
   - Report a skipped learning step instead of skipping silently.
   - Unblock workflows after a model outage.
2. **Port fact-key corroboration into `autolearn`** (or send its claims to the backend), so verification can be automatic again.
3. ~~**Enforce the code fingerprint on proposals.**~~ Done on 20 October: the cycle's worker gate checks each release-controlled bot's code fingerprint before it runs ([releases](releases.md)).
4. ~~Add a "suspended" bot state, and let the owner change a bot's budget.~~ Done the same day. Also done the same day:
   - a model server found down no longer blocks a learning request;
   - the readiness check reports learning steps that did not run;
   - the secret scan covers JSON, log and `.jsonl` files.
5. **Enforce compute and department budgets** instead of only alerting, and have workers report their compute usage.
6. **Add the missing pieces of the trading model.** A rotation that keeps the sale's proceeds is handled. Partial fills and liquidity limits matter only at larger sizes.
7. **Add an NSE holiday calendar**, and confirm the market data licence.
8. **Add CI**, and include the remaining suites in `npm run verify`.
9. **Fix smaller operational items.**
   - **Backups:** they do not reach a container's database volume.
   - **Credential backups:** the `.env` copies in `.local/env-backups` contain credentials. Delete old ones; they never leave the machine, and `.local` is not committed.
   - **Secret scan:** it does not look at `.jsonl` or `.log` files.

## Also fixed later on 14 October (owner-free, with tests)

**Operations.**
- **Rate limit:** the organisation's own authenticated workers are no longer rate-limited; anonymous requests and wrong tokens still are.
- **News triage:** it drains a backlog (up to 5,000 items a run) and runs fresh on every cycle.
- **Alert delivery:** a failed delivery fails its step so it escalates, and the outbox gets one line per alert.
- **Linux:** the cycle finds the research Python on Linux too.
- **Feed verification:** its report no longer looks like a feed configuration.

**Model use.** The model allocator reports its usage to compute usage.

**Organisation.**
- **Hackathons:** a contest's evaluation window must open after its entry deadline.
- **Department leads:** a retired lead is removed from the role and no longer blocks bot births.
