## The news was collected but never read

A check of the 27 Oct cycle found three steps skipped, every day, since the move:
- `claims-and-fact-check`, `headline-reader` and `chain-links` were all skipped. The owner configuration
  `.local/claims/autolearn.json` did not exist on this machine, and was not in the data repository either.
- So no news was ever fact-checked. The fact-checker is also what reviews the collected evidence, which is why 42
  items had waited over 24 hours.
- The headline reader, the chain links and the debate had no verified news.

**Fix:**
- The configuration is back. The verified news goes to `debate-bull`, `debate-bear` and `tradingagents`; no primary
  sources; held 7 days for corroboration; at most 20 model calls a cycle.
- STARTUP now checks for the file, so a move cannot lose it again, and `export-data` carries it.

**BusinessLine** failed once on 27 Oct (`FEED_UNREACHABLE`). A retry fetched 25 new items, so it was a one-off.

**Running the chain by hand found two more faults:**
- **The claims `.env` reader kept the quotes.** `PRINCIPALS_JSON` is quoted in `.env`; Node's `--env-file` strips the
  quotes, but `autolearn.env_file` did not, so a manual run stopped at once with a JSON error. The daily cycle was not
  affected, because it passes the cleaned value down. The reader now strips matching quotes as Node does.
- **Windows briefly locked a state file.** The fact-checker stopped mid-cycle on `Access is denied` while replacing
  `decisions.json`. Every atomic replace now retries for up to a few seconds, as the trading desk's `batch.save`
  already did: in claims, the knowledge index, TradingAgents and Hermes.

The first real run queued 149 news items. Two cycles then ran end to end, with the model reading 20 items in each:
- the model read 40 items: 3 claims accepted, 27 rejected by the quote check;
- the fact-checker decided 20: 18 had no checkable claim, and 2 were older than 7 days with no second source;
- no headline is verified yet, because that needs two independent sources reporting the same fact.

**Throughput.** 20 model calls took about 9 minutes, but about 75 items arrive a day, so the backlog could never
clear. The limit is now 80 calls a cycle (about 35 minutes), and the newest news is read first: today's news matters
most, and an item older than 7 days can no longer be corroborated in time.

**R&D:** a model timeout no longer fails the whole `rnd-scout` step. The model's new ideas wait for another day, the
failure is recorded (`model-failed`), and the catalogue is still screened. Both of 27 Oct's `rnd-scout` failures were
model timeouts.

**Rule bot release:** today's code is release v3, running as a canary under the standing approval to trial new
releases, so the bot may trade. The agenda item to make v3 fully active waits for the owner, or for the standing
approval to promote canaries once it has live results.

## Evening: moving to the home laptop, and closing the model gap

The owner will run the organisation on a home HP EliteBook (no Claude there). Built so that it takes two commands:
- **`npm run handover`** on the office laptop. It waits for a running job, stops the supervisor, takes a verified
  backup, exports the data and pushes the data repository and `dev`. Then the office supervisor refuses to start again
  (OPS-04: one machine only; `--take-back` undoes it).
- **`scripts\setup-machine.ps1`** on the new machine (OPS-05, Windows PowerShell 5.1+). It does everything else:
  - programs, both repositories, the data, a secrets check, three Python environments;
  - the database restore, the knowledge index and the model;
  - then the model work below;
  - checks, and a start (optionally a scheduled task, so it survives reboots).

  Safe to re-run.

**Five ways to close the gap to a frontier model:**
1. **Speed:** `npm run model:tune` measures thread counts with llama-bench on the machine. The office laptop's
   i7-1355U has 2 performance and 8 efficiency cores, where the default is often not the fastest.
2. **A second pass in the debate** (MODEL-CHECK-01): the debater re-reads its argument against the data and corrects
   it. Found by the exams today: the model called an unverified press report "the verified evidence", and misread "41%
   were stopped out" as "41% recover". The exams now judge the checked argument and fail forbidden phrases
   (`mustNotMention`).
3. **A bigger decision model:** `npm run model:upgrade` picks the largest candidate the RAM fits (Qwen 3.5 or Qwen 3,
   14B or 9B/8B). The download is pinned to Hugging Face's published sha256 at an exact commit. It is served on port
   8081, and **used for the debate and TradingAgents only if our exams say SHIP**; the 4B keeps the bulk work. The
   supervisor starts it optionally, and the cycle falls back to the 4B if it does not answer.
4. **The laptop's graphics:** the Vulkan build of llama.cpp, verified against GitHub's published sha256, kept only if
   measured at least 10% faster than the CPU build.
5. **Fine-tuning on its own outcomes:** later, once months of scored calls exist (B12).

**TradingAgents trial.** The first trial found a key bug that would have failed every Friday call (401: its provider
reads `OPENAI_COMPATIBLE_API_KEY`). The second trial measured the speed:
- about 4 minutes a call, as every later agent reads all earlier reports;
- one prompt reached 10,484 tokens, which took 9 minutes just to read;
- about 2.5–3 hours per share, so 8 shares a Friday would take about a day.

It now rates its holdings plus 2 rotating shares a week (all 8 within 4 weeks) with 3 tool rounds instead of 8.

**Exams:** 11 debate cases, all passed on the real model before the stricter judging. Four new ones: don't chase a big
day, a stop is not an edge, press is not proof, and the bull answering with the sector's strength.

## Evening: the system closes its own gaps

The owner asked for an "autonomous system": a gap the organisation can close within its safety rules is closed in
code, not added to the weekend list.
- **Quote-checked news tier (NEWS-06).** Verification needs two independent publishers, which was rare with three
  feeds. The debate now also reads claims whose quote the fact-checker found word for word. They are labelled
  "single source, not verified", and citations stay limited to verified evidence ([claims](../../integrations/claims/README.md)).
- **Verified backups.** Every new backup is checked by `verifyBackup` straight away, and a failing one is an error.
- **Supervisor self-healing:**
  - a second supervisor refuses to start while one is alive;
  - a supervisor more than 10 minutes past a job it never started logs a watchdog entry and starts its own
    replacement (under the scheduled task, `--managed`, it only exits and the task restarts it).
- **Results days from the press (NEWS-07).** The results-day lesson depended on a calendar file nobody kept.
  - `results_calendar.py` reads results dates from the headlines by fixed rules, for example "to declare results on
    Oct 17" and "Q2 Results Today Live: …".
  - The dates build up beyond the 500-item headline history, and join the events calendar as `source: press`.
  - Owner entries still win.
  - On today's 500 headlines it found 27 dates, including 17 Oct for HDFC, ICICI and Axis Bank: the day they reported.
  ([events calendar](../events-calendar.md))
- **The owner list loses its false items.**
  - Today's digest asked the owner about 4 things. The reliability and unknown-failure items were already fixed in code,
    after the 16:05 run.
  - The evidence-backlog alarm fired on evidence the fact-checker was deliberately holding: it waits 7 days for a
    second publisher. It now fires only past 8 days, when the fact-checker must be stuck ([alerts](../alerts.md)).
- **Why nothing was ever verified (CLAIMS-03).** The model named one fact many ways: the Jio listing-day gain was
  `share price`/`DEBUT`, `share price`/`MARKETDEBUT` and `ipo premium`/`DEBOUT`, and "Wednesday" differed per article.
  - Fixed rules now give each fact one name: quarters become `Q2FY27`, weekdays become dates, debut becomes
    `LISTINGDAY`, synonyms become one metric.
  - The event type no longer splits a fact (backend registry too).
  - A share price counts for a share only when the quote names it.
  - "Reliance Jio" and "Reliance Group" are no longer Reliance Industries.
  - On today's claims nothing new corroborates: the only overlap was Jio's own price, correctly kept off Reliance
    ([claims](../../integrations/claims/README.md)).
