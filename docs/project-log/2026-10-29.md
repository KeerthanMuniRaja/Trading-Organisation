## Toward the full vision: the parts that need no owner decision

A read-only map of "the system develops itself" found where each path stops:
- **Strategies:** ideas are invented and screened daily, but only on seen history. After 25 ideas the bar is p < 0.002,
  and the best idea is at p = 0.10. Every new idea raises the bar, so nothing can pass.
- **Code:** the system never writes code itself. The furthest it goes is AUTO-05: a person's code fix to the rule bot
  becomes a canary release by itself.
- **The training machinery (W12):** six steps answer "disabled" until the owner switches their policies on. The worker
  that does their work (exams, dataset fits, trial reviews) was never in the cycle, so switching on would only have
  filled queues.

Built today:
- **The department worker in the cycle (W12).** `department-researcher` (up to 10 minutes) and `department-evaluator`
  run through the existing launcher (`run-department.mjs`: one role's credential, the pinned skfolio environment,
  supervised session).
  - They run only once an academy or lifecycle cycle in this run answered with its policy on. A new runner feature
    (`when`) lets a step depend on earlier results in the same run.
  - Until the owner's W12 decision they are skipped, with the reason given.
- **R&D forward tests (RND-04, `rnd_forward.py`).**
  - Once a month, the best unserved idea is registered and judged only on later months.
  - At most 5 tests at once; at 24 months, a pass needs one-sided t ≥ 2.5 and a positive average.
  - A rule-code change ends a test. New ideas in the ledger do not (`rnd_scout.code_fingerprint`).
  - The first registration is `momentum-6m-top3-quarterly`, judged from November 2026 ([R&D scout](../rnd-scout.md)).
- **Not done yet:** release renewal for the TradingAgents bot and the model allocator. Renewal evaluates a code fix on
  the rule bot's regime-study fitness, and the model-driven bots have no equivalent measure yet. That comes first.
