# Updated-code review and development

Reviewed the clean checkout at `023de53`, concentrating on the new claims/autolearn and trading-desk learning paths, fitness reporting, and their backend review boundary. The commit contains 163 changed files; this was a focused review, not a complete audit of every forecasting, dashboard or fine-tuning implementation.

## Fixed

- **Contradicted evidence could be approved:** `evidence_decision` returned verified when any claim was corroborated or primary-source-supported before checking other claims for contradiction. Contradictions now take precedence and hold the evidence for review.
- **Lesson approval preceded verification of the stored lesson:** both automatic learning workers checked a local proposal, approved its supplied backend ID, then read back the verified knowledge list. This allowed a mismatched lesson to become visible before detection; the bounded knowledge list could also omit it. The backend now supports an optional `expected: {content, evidenceId, botId}` on lesson review, compares these fields in the approval transaction, and refuses mismatches before publication. Both automatic workers send expectations derived from their review inputs. Existing manual review requests remain compatible.
- **Credentialed requests followed redirects:** the shared Python backend client now refuses redirects and explicitly rejects responses over 2 MB. A loopback test confirms it never requests the redirected destination.
- **Workers inherited unrelated secrets and injection settings:** the shared runner now inherits only a small set of OS runtime environment variables, adds the selected role credential, and includes model credentials only for model steps. Tests cover unrelated provider/owner credentials and Python/Node injection variables. This is environment minimisation, not filesystem or process sandboxing; workers still run as the same OS user.

## Remaining findings

- **Claim equivalence is not established.** `claims.corroborate` groups by symbol/event type with publications chained within 72 hours; `summarise` counts origins and compares model-assigned price directions. Two positive earnings reports can concern different measures or periods. Opposite price opinions can coexist without factual contradiction. `verify` checks quote presence and company/date constraints, not whether the model's paraphrase follows from that quote. Treat this as research triage, not factual proof; semantic claim matching and conservative review gates are still needed.
- **Evidence binding follow-up implemented:** automatic evidence-review clients now send expected content, source, kind and publication time, plus title/URL for source observations. The backend checks these atomically before changing review status and rechecks approved-source and publication-time eligibility on verification. Local cached records still are not an independent security boundary; exact-ID retrieval and current-eligibility reconciliation remain needed for downstream exports.
- **Headline reconciliation follow-up implemented:** export now reconciles exact IDs with `/v1/evidence/status`, compares snapshot content/provenance and recalculates corroboration after excluding withdrawn support. It clears previous output before reconciliation and leaves it empty on failure. This remains an export-time snapshot; withdrawals after lookup or during idle periods require another reconciliation, not an assumption of permanent eligibility.
- **Synthetic fitness remains limited.** The desk fitness module reports recommendations and does not change lifecycle authority. Its directional comparisons and statistical results should not be treated as evidence of profitable autonomous trading or a basis for automatic retirement without further evaluation.
